AnimateBanana · reviewer handbook

Annotating AnimateBanana

Six stages, each with a gate. You move on when the gate opens — not when the screen looks finished. Every button named here is the label you'll see.

The one rule

A stage is done when both halves pass: the machine check (does it render / validate / export) and your sign-off. Approving something broken does not open the gate, and approving something does not freeze it — if a later edit breaks the sequence, the gate closes again on its own.

The server enforces this, not just the button. Skipping ahead returns 409 naming the stage that blocks you.

Approve vs Promote

Two buttons that sound similar and do different things. This is the single most common confusion, so it's worth reading once:

ButtonWhat it doesWhen
Approve stage Records that you judged this correct. Opens the gate. Every stage, once you're satisfied
Promote Copies your edit over the pipeline's own file. Changes what downstream stages read. Only after you've pasted in a replacement

Promoting does not approve, and approving does not promote. If a gate stays shut after you've promoted, you still need to approve.

The six stages

1aD2C

Diagram code

The figure redrawn as TikZ or SVG. This is the landing screen — pick a sample from the left.

  1. Click Render diagram and compare it against the source figure beside it.
  2. Wrong or missing content? Click Copy prompt, then Download image, paste both into a stronger model.
  3. Paste its answer into the code box and click Save as human_code.
  4. Render again. When it's right, Approve stage.
1brasters

Raster placement

Photographs and screenshots can't be drawn, so they're cropped from the source and spliced in. Boxes sit over the figure.

  1. Drag a box's body to move it; drag a corner to resize. Amber means you've adjusted it.
  2. Click Insert all boxes.
  3. Render diagram to check the crops landed where you meant.
  4. Approve stage.

If a warning says your diagram code changed after these were spliced, click Re-run (force) first — the splice is a snapshot and is out of date.

2bXML

Structure

The diagram's hierarchy: what contains what. Edit as a tree or as raw XML — the two stay in sync.

Element ids here are load-bearing. Every focus entry in the sequence is checked against them, so deleting a node breaks steps later.

Text labels are deliberately absent from this XML. That's by design, not a defect — don't add them.

2csequence

Animation sequence

The order things appear and what each step focuses on. Validation runs as you type.

  1. Read the step list. To rebuild it, click Sequence (2c→2d + narrate).
  2. To improve it by hand: Copy prompt — it already contains the code, the XML and the style. Paste the result back and Save.
  3. Fix until validation reports zero problems, then Approve stage.

Sequence, no critic skips the repair pass — useful to see what the model produces unaided. Expect violations; that's the point.

2enarration

Narration — not reviewed

Written into an already-valid sequence, touching only the spoken script. No gate, no approval, nothing to click. It runs as part of every sequence build.

3aanimation

Animation

The last place you can edit code. Reached from the sequence screen's Next: animation →.

  1. Compile → slides + video builds the frame deck and an mp4. Watch the video for motion; step the frames to check one moment.
  2. Wrong? Copy prompt carries everything the designer got — sequence with narration, diagram code, style block.
  3. Paste a fix into the code box, Save, compile again.
  4. Approve stage.

Render animation (first frame) is the quick check — seconds rather than a full deck.

Editing code: the three places

These are the only points where your text replaces the model's. Each saves beside the pipeline's own file — nothing is overwritten until you promote.

2c or 2d — which sequence slot

Saving at 2c puts your correction where the critic still refines it. Saving at 2d takes your version as final. Improving a draft → 2c. Want exactly what you wrote → 2d.

Reading a gate

1a diagram code    ✓ code renders          ✗ reviewer approved
2c sequence        ✗ sequence validates    ✗ reviewer approved
                     └ 3 violation(s): root node 't2' has depth 2

A tick passes; a cross blocks, and the detail says why. The Next button stays disabled until every check on the current stage passes.

When you're stuck

It won't compile and you can't fix it. Use Discard this annotation. It deletes your edits, reverts any promotion, and marks the sample written off — with your reason kept, so nobody repeats the work. That's a real outcome, not a failure.

The screen looks empty. Usually the style or target was switched: artifacts are stored per style and per target, so the other one still has your work. Switch back and it reappears.

You got a 409. An earlier stage isn't finished; the message names it. Re-running an earlier stage is always allowed — that's how you unblock yourself.

Frames look like the old animation. Compiling rebuilds them, but re-running 3a doesn't. Compile after any re-design.
